# Динамический список: запрос, отбор, обновление, подсчёт

Читай, когда пишешь или правишь форму списка: свой запрос, отбор и порядок из кода, изменение типового списка, подсчёт строк, медленный список. Метки: **[надёжно]**, **[проверить]** (сверь по справке платформы и по коду базы; здесь модель чаще всего выдумывает).

## Ловушки (сначала)
1. Динамический список работает на движке компоновки данных. Его отбор, порядок и условное оформление — это настройки компоновщика (`Список.КомпоновщикНастроек`), а не перебор строк. Не читай и не фильтруй строки списка на клиенте циклом. **[надёжно]**
2. `ПроизвольныйЗапрос` это булево свойство: Истина значит свой текст запроса, Ложь значит запрос строится автоматически по основной таблице. Свой текст запроса без указанной основной таблицы теряет часть возможностей: отбор и порядок по полям основной таблицы, ограничение доступа к записям по основной таблице работают корректно только когда она задана. **[проверить]**
3. `Список.ТекстЗапроса` меняй на сервере (обычно в `ПриСозданииНаСервере`). Расчёт на клиенте через серверный вызов с повторным присвоением даёт гонки и лишние обновления. **[проверить]**
4. Правка запроса типового списка через копирование формы ломает обновляемость конфигурации. Меняй запрос расширением формы (перехват `ПриСозданииНаСервере`), а не копией. **[проверить]**
5. Запрос динамического списка не обычный запрос: пакет, временные таблицы и `ИТОГИ` не поддерживаются, поля должны иметь псевдонимы, в выборке нужно ключевое поле (обычно `Ссылка`). Точный перечень ограничений сверь по справке версии. **[проверить]**
6. Функции общих модулей в тексте запроса ограничены (разрешены только если так настроено и функция подходит для серверного вычисления в запросе). Не вставляй вызов "на всякий случай". **[проверить]**
7. Динамическое считывание данных читает порциями (значение по умолчанию **[проверить]**: в справке платформы не указано); свойства списка, зависящие от полного набора строк (итоги по всему списку, подсчёт всех строк), так не получить.
8. Параметры запроса (`&Имя`) задавай через `Список.Параметры.УстановитьЗначениеПараметра("Имя", Значение)`; неизвестное имя параметра даёт исключение.

## Основные приёмы

Отбор и порядок из кода (платформенный способ):

```bsl
Отбор = Список.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
Отбор.ЛевоеЗначение  = Новый ПолеКомпоновкиДанных("Организация");
Отбор.ВидСравнения   = ВидСравненияКомпоновкиДанных.Равно;
Отбор.ПравоеЗначение = Организация;
Отбор.Использование  = Истина;
Отбор.РежимОтображения = РежимОтображенияЭлементаНастройкиКомпоновкиДанных.Недоступный; // пользователь не видит
```
Если в проекте есть клиент-серверные методы БСП для динамических списков, предпочитай их: в БСП 3.1.9.232 подтверждены `ОбщегоНазначенияКлиентСервер.УстановитьПараметрДинамическогоСписка`, `УдалитьЭлементыГруппыОтбораДинамическогоСписка`, `НайтиЭлементОтбораПоПредставлению`. Остальные названия и сигнатуры возьми из модуля в своей базе **[проверить]**.

Свой запрос:

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
    Список.ТекстЗапроса = "ВЫБРАТЬ
        |	Док.Ссылка КАК Ссылка,
        |	Док.Номер КАК Номер,
        |	Док.Дата КАК Дата
        |ИЗ
        |	Документ.ЗаказКлиента КАК Док
        |ГДЕ
        |	Док.Организация = &Организация";
    Список.Параметры.УстановитьЗначениеПараметра("Организация", Организация);
КонецПроцедуры
```
`ТекстЗапроса`, `ОсновнаяТаблица` и `ДинамическоеСчитываниеДанных` устанавливаются из серверного кода; в БСП это делается одним вызовом `ОбщегоНазначения.УстановитьСвойстваДинамическогоСписка(Элементы.Список, СвойстваСписка)`. Из текста запроса эти свойства не включаются.

Обновить после смены параметра или отбора: `Элементы.Список.Обновить()`.

Подсчёт строк с учётом отбора и поиска: возьми исполняемую схему и исполняемые настройки списка, очисти в настройках поля итогов, структуру и выбор, добавь ресурс `КОЛИЧЕСТВО(Ссылка)`, скомпонуй и выведи в таблицу значений. Не считай количество через цикл по клиенту. **[проверить]** метод получения исполняемых схемы и настроек: он доступен у элемента формы начиная с версии платформы 8.3.6; проверь, что есть в твоей. Эти методы расширения таблицы формы для динамического списка доступны только на сервере.

Эскиз (структура схемы и настроек, **[проверить прогоном на своей версии]**):

```bsl
&НаСервере
Функция КоличествоСтрокСписка()
    // схема и настройки именно списка, с отбором, поиском и пользовательскими настройками
    Схема = Элементы.Список.ПолучитьИсполняемуюСхемуКомпоновкиДанных();
    Настройки = Элементы.Список.ПолучитьИсполняемыеНастройкиКомпоновкиДанных();

    Схема.ПоляИтога.Очистить();
    Итог = Схема.ПоляИтога.Добавить();
    Итог.ПутьКДанным = "КоличествоСтрок";
    Итог.Выражение   = "КОЛИЧЕСТВО(Ссылка)";

    Настройки.Структура.Очистить();
    Настройки.Выбор.Элементы.Очистить();
    // добавить в Настройки.Выбор поле "КоличествоСтрок" и вывести детальные записи в таблицу значений
    // (процессор вывода в коллекцию значений, см. skd-programmatic.md)
КонецФункции
```
Не собирай новую схему с нуля из `Список.ТекстЗапроса`: исполняемая схема уже учитывает отборы и поиск пользователя.

Условное оформление списка: через `Список.УсловноеОформление` на сервере; не меняй цвета ячеек из клиентского обработчика строки.

## Правила
- Пользователь списка видит только то, что разрешено правами: не обходи ограничение доступа запросом "в обход" (`РАЗРЕШЕННЫЕ` и ограничения записей действуют на запрос списка).
- Медленный список: проверь план запроса и индексы по полям отбора и порядка прежде чем править код. Первый кандидат: условие по неиндексируемому реквизиту, соединение с большой таблицей, разыменование ссылочных полей через точку (замени явным соединением).
- Поле составного типа в запросе списка разыменовывай через `ВЫРАЗИТЬ`, иначе строится соединение со всеми таблицами типов (см. `composite-types.md`).
- Характеристики из метаданных работают и в динамических списках; отдельно подключать их не нужно.

## Как проверить
Форма в тест-базе: открыть список, выставить отбор из кода, убедиться, что строки соответствуют; подсчёт строк исполняемой схемой совпадает с видимым результатом. Без этого поведение непроверенное.

## Не проверено
Точный перечень ограничений запроса в твоей версии платформы, поведение функций общих модулей в запросе, влияние динамического считывания на итоги.
