# СКД из кода: схема, настройки, компоновка, вывод

Читай перед тем, как писать код, который сам собирает и выполняет компоновку данных (отчёт без формы, выгрузка в таблицу значений, проверка запроса, подсчёт строк). Метки: **[надёжно]** — устойчивое свойство платформы; **[проверить]** — сверь по справке платформы и по реальному коду базы, прежде чем опираться.

## Ловушки (сначала)
1. Компоновщик настроек без `Инициализировать` не знает полей: список доступных полей пуст, отбор и группировка не добавляются. **[надёжно]**
2. `Компоновщик.Настройки` — живые настройки: правка применяется сразу. `Компоновщик.ПолучитьНастройки()` возвращает копию: правь копию и забыл `ЗагрузитьНастройки` — изменение потеряно. **[надёжно, подтверждено прогоном]**
3. `ЗагрузитьНастройки` может сбросить значения параметров, которых нет в загружаемых настройках: после загрузки перечитай параметры и при необходимости задай заново. **[проверить прогоном, в справке платформы не описано]**
4. Вывод в таблицу значений: поддержаны только группировки и детальные записи. Таблицы, диаграммы, вложенные отчёты не выводятся; условное оформление и макеты оформления игнорируются; папки в выбранных полях игнорируются. **[проверить по руководству разработчика: в справке платформы этих ограничений нет]**
5. Для вывода в коллекцию значений макет строится с генератором: без него колонки получатся не те.
6. Параметр без включённого `Использование` в запрос не попадёт. `УстановитьЗначениеПараметра(Имя, Значение)` само включает `Использование`, а при неизвестном имени параметра вызывает исключение: имя бери из настроек, не угадывай.
7. Не угадывай имена полей: бери из `Схема.НаборыДанных[...].Поля` или из доступных полей компоновщика.

## Порядок объектов
Схема и настройки → макет → процессор компоновки → процессор вывода. Каждый объект можно сериализовать в XML, это удобно для отладки.

```bsl
Схема = ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных");   // или из XML / из временного хранилища
Компоновщик = Новый КомпоновщикНастроекКомпоновкиДанных;
Компоновщик.Инициализировать(Новый ИсточникДоступныхНастроекКомпоновкиДанных(Схема));
Компоновщик.ЗагрузитьНастройки(Схема.НастройкиПоУмолчанию);

Настройки = Компоновщик.Настройки;
Настройки.ПараметрыДанных.УстановитьЗначениеПараметра("НачалоПериода", НачалоМесяца(ТекущаяДата()));

Отбор = Настройки.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
Отбор.ЛевоеЗначение  = Новый ПолеКомпоновкиДанных("Организация");
Отбор.ВидСравнения   = ВидСравненияКомпоновкиДанных.Равно;
Отбор.ПравоеЗначение = Организация;
Отбор.Использование  = Истина;

ДанныеРасшифровки = Новый ДанныеРасшифровкиКомпоновкиДанных;
КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
Макет = КомпоновщикМакета.Выполнить(Схема, Настройки, ДанныеРасшифровки);

Процессор = Новый ПроцессорКомпоновкиДанных;
Процессор.Инициализировать(Макет, , ДанныеРасшифровки);

ТабДок = Новый ТабличныйДокумент;
Вывод = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
Вывод.УстановитьДокумент(ТабДок);
Вывод.Вывести(Процессор);
```

Вывод в таблицу значений:

```bsl
Макет = КомпоновщикМакета.Выполнить(Схема, Настройки, , , Тип("ГенераторМакетаКомпоновкиДанныхДляКоллекцииЗначений"));
Процессор.Инициализировать(Макет);
Результат = Новый ТаблицаЗначений;
Вывод = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВКоллекциюЗначений;
Вывод.УстановитьОбъект(Результат);
Вывод.Вывести(Процессор);
```
Сигнатуры по справке платформы 8.3.27: `КомпоновщикМакетаКомпоновкиДанных.Выполнить` принимает 7 параметров (схема, настройки, данные расшифровки, внешние наборы данных и др., остальные необязательные), `ПроцессорКомпоновкиДанных.Инициализировать` принимает 6, `Вывести(Процессор, ВозможностьПрерывания)` у процессоров вывода. Полный список параметров смотри в справке своей версии. `Вывести` в коллекцию значений возвращает объект результата.

## Правила
- Схему чужого отчёта или формы получай через `ПоместитьВоВременноеХранилище` и адрес, а не лезь в её макет напрямую.
- Меняешь структуру (группировки, поля, порядок): правь `Компоновщик.Настройки.Структура` и `Выбор`, затем снова `Выполнить`. Готовый макет не правится.
- Расшифровку (`ДанныеРасшифровки`) передавай в оба вызова: в `Выполнить` и в `Инициализировать`, иначе расшифровки не будет.
- Большие выборки: выводи порциями из цикла `Пока Элемент <> Неопределено`, а не накапливай всё в память, если результат нужен только для вывода.
- Хочешь только проверить, что запрос схемы компонуется: выполни `Выполнить` и переберите процессор до конца в тест-базе. Одной сборки макета мало.

## Как проверить
1. Структуру схемы: `scd validate` (`onec_metadata`), если схема лежит файлом.
2. Поведение: сценарий в `smoke_runner` (`onec_verify.py smoke`) в тест-базе: скомпонуй, выведи в таблицу значений, проверь число строк и значения ключевых полей.
3. После правки настроек в коде перечитай их из компоновщика и убедись, что изменение осталось (ловушка 2).

## Не проверено
Точные сигнатуры в твоей версии платформы, поведение расшифровки при внешних наборах данных, порядок работы с `ВнешниеНаборыДанных`.
