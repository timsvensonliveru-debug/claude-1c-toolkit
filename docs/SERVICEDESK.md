# ManageEngine ServiceDesk Plus: коннектор API v3

`scripts/servicedesk.py` читает заявки и создаёт заявку по шаблону через [API v3 ServiceDesk Plus](https://www.manageengine.com/products/service-desk/sdpod-v3-api/) (разделы requests и request_templates). Только стандартная библиотека Python, без MCP и сторонних пакетов.

## Подключение (один раз)
1. В профиле пользователя ServiceDesk Plus сформируйте ключ: раздел **API Key generation**. Права ключа: только чтение и создание заявок.
2. В `.env` (шаблон `.env.example`, сам `.env` не коммитить) задайте две переменные:
   - `SD_BASE_URL` адрес портала до `/api/v3` (для облачной версии вместе с `/app/<портал>`);
   - `SD_API_KEY` ключ из шага 1.
   Необязательно: `SD_AUTH_SCHEME` (`authtoken` по умолчанию, ключ в заголовке `authtoken`; `oauth` отправляет `Authorization: Zoho-oauthtoken ...`), `SD_CONFIG` путь к конфигу шаблонов и групп. Заголовок `authtoken` проверен на рабочем портале (локальная установка), для облачных порталов с OAuth задайте `oauth`.
3. Скопируйте `config/servicedesk.example.toml` в `config/servicedesk.toml` и впишите имена шаблонов и групп. Обычный ключ часто не читает списки шаблонов и групп (ошибки 403 и 404), поэтому имена берутся из конфига, а не запрашиваются.

Ключ нигде не печатается и не сохраняется, в сообщениях об ошибках его нет. Адрес должен быть `https` (внутренний узел по `http` только при `SD_ALLOW_HTTP=1`), узел можно закрепить переменной `SD_ALLOWED_HOSTS` (через запятую), перенаправление на другой узел отклоняется.

## Чтение заявок
```bash
python scripts/servicedesk.py list --group "Поддержка" --status Open --since 2026-10-01 --until 2026-10-21 --limit 300
python scripts/servicedesk.py list --technician "Имя Исполнителя" --json
```
Фильтры соединяются через AND и собираются в `list_info.search_criteria` (поля `group.name`, `status.name`, `technician.name`, `created_time`). **Проверено на рабочем портале 22.10.2026:** `list`, фильтр по группе (`group.name`) и по дате (`--since`) работают. Не проверены `--status` и `--technician` (имена полей и значения статусов сверьте с вашим порталом), создание заявки не проверялось. Свои условия: `--criteria-json файл` (массив объектов `search_criteria`, добавляются к фильтрам). Выгрузка постраничная: `start_index` растёт на `row_count`, пока `has_more_rows`, не больше `--limit` записей, размер страницы `--page-size` (до 100).

Вывод по умолчанию: номер, тема, статус, группа, приоритет, шаблон, время создания. **Структурные поля заявителя и исполнителя и вложения не выводятся** без флагов `--with-people` и `--with-attachments`. Тема и описание выводятся как есть и могут содержать ФИО, почту, телефон или номера договоров: проверьте их на персональные данные перед тем, как показывать модели.

## Создание заявки по шаблону
```bash
python scripts/servicedesk.py create --template access_request --subject "Доступ к базе" --description "..." --group support
```
По умолчанию **сухой прогон**: печатается тело запроса, ничего не отправляется. Отправка только с `--send` и только после ручного подтверждения: команда показывает тело и просит ввести слово `отправить`. Без интерактивного терминала отправка отказывает. Подтверждение защищает от случайного запуска, но не является механизмом авторизации: процесс с терминалом и доступом к окружению его автоматизирует. Запускайте отправку сами (в сессии агента с префиксом `! `), а ключу выдайте только нужные права.

## Ограничения
- Имя шаблона и группы должны точно совпадать с именем в портале. Для шаблонов с обязательными полями (заявитель, категория) добавьте эти поля в шаблон портала, а не в команду.
- Время периода (`--since`, `--until`) считается по UTC, границы дня сдвиньте при необходимости.
- Облачные порталы разных регионов отличаются адресом, проверьте `SD_BASE_URL` по документации портала.

## Тесты
`python -m pytest tests/test_servicedesk.py` работает без сети: транспорт подменяется, примеры ответов лежат в `tests/fixtures/servicedesk/`. Проверяются сборка `list_info`, пагинация, ошибки 401, 403 и 404, скрытие персональных данных и порядок подтверждения отправки.
