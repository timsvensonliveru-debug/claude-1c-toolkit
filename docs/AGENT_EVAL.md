# Оценочный стенд агента

Задачи с проверяемым признаком верного ответа, чтобы видеть, где агент ошибается на 1С, и усиливать скиллы и справочники там, где он спотыкается. Ловушки взяты из практики: СКД из кода, пользовательские настройки, динамические списки, дополнительные реквизиты, составные типы, NULL и Неопределено, замечания SonarQube.

## Как устроено
- Задачи: `tests/agent_eval/tasks/<id>.json` (промпт, тема, `must` и `must_not` регулярными выражениями, пояснение).
- Проверки детерминированные: они ловят наличие ключевых элементов верного ответа, а не оценивают текст целиком. Провал по теме сигнал усилить справочник.
- Запуск: `python scripts/agent_eval.py run --repeat 3` (по умолчанию `claude -p` из корня набора, скиллы подхватываются из `.claude/skills`; свою команду задайте `--cmd` или `AGENT_EVAL_CMD`). `--bare` запускает без скиллов набора в пустом каталоге: сравните две таблицы, чтобы увидеть вклад набора.
- `python scripts/agent_eval.py list` и `check <id> <файл-с-ответом>` работают без запуска агента.
- Результаты: `~/.operkontur/agent_eval/<время>.json`, сводка по темам в конце запуска.

## Как добавить задачу
Файл `tests/agent_eval/tasks/<id>.json`: `id`, `topic`, `prompt` (с оговоркой «файлы не создавай»), `must` (все должны найтись), `must_not`, `note` (почему так). Проверка `pytest tests/test_agent_eval.py` убеждается, что выражения компилируются, а ключевые слова задачи проходят её проверку. Задачи без данных организаций, только открытые факты платформы.

## Ограничения
Прогон тратит токены агента и зависит от модели, поэтому делайте несколько повторов. Регулярные выражения не заменяют оценку человека: пройденная задача значит, что ключевые элементы есть, а не что ответ безупречен.
