# Сайт или веб-приложение рядом с 1С на PostgreSQL

Сайт и 1С не стоит держать в одном экземпляре PostgreSQL: требования противоположные. Если разнести нельзя, параметры, у которых контекст `user` или `superuser` (например `work_mem`, `join_collapse_limit`, `standard_conforming_strings`, `max_parallel_workers_per_gather`), можно задать для одной базы или роли командой `ALTER DATABASE ... SET`. Параметры с контекстом `postmaster` (`max_connections`, `max_locks_per_transaction`, `shared_buffers`) глобальные на весь экземпляр, их так не разделить. Проверка: `SELECT name, context FROM pg_settings WHERE name = '...';`.

| Параметр | Для 1С | Для сайта |
|---|---|---|
| Соединения | сотни долгоживущих сеансов, `max_connections` от 500 | много коротких соединений, нужен pgbouncer; PGTune для WEB берёт 200 |
| Пул соединений | режим transaction логически несовместим: временные таблицы 1С привязаны к сеансу, **[не подтверждено]** | режим transaction допустим, если приложение не использует возможностей сеанса ([справка pgbouncer](https://man.archlinux.org/man/pgbouncer.1.en.txt)) |
| `standard_conforming_strings` | `off` | по умолчанию (`on`) |
| `temp_buffers`, `max_locks_per_transaction` | увеличены под временные таблицы | по умолчанию |
| `join_collapse_limit`, `from_collapse_limit` | 20 | по умолчанию (8) |
| Параллельные запросы | отключены | можно оставить, особенно для отчётов |
| `work_mem` | фиксированное 32–256 МБ | считается от числа соединений ([PGTune](https://github.com/le0pard/pgtune/blob/master/src/features/configuration/configurationSelectors.js)) |
| `synchronous_commit` | по ИТС `off`: при сбое сервера теряются последние подтверждённые транзакции (целостность базы не страдает). На базах с обменами и операциями с внешними последствиями оставлять `on` | обычно `on`, если нельзя терять подтверждённые операции; можно задать на базу |
| Размер пула pgbouncer | не применимо | подбирается нагрузочным тестом, числа в источниках нет, **[не подтверждено]** |

Правила. Для сайта на общем экземпляре отдельная роль и отдельная база. Параметры сеанса 1С на сайт не переносить и наоборот. Мониторинг по каждой базе раздельно: `pg_stat_database` и `pg_stat_statements` с фильтром по `dbid` (статистика выражений собирается по всему экземпляру).
