# Дополнительные реквизиты и сведения (подсистема "Свойства")

Читай, когда нужно прочитать, записать или показать пользовательское свойство объекта (дополнительный реквизит или сведение), использовать его в отчёте или доработать форму. Метки: **[надёжно]**, **[проверить]** (сверь по справке и по коду библиотеки подсистемы в своей базе: версии библиотеки отличаются).

## Ловушки (сначала)
1. Не путай два понятия. **Дополнительный реквизит** хранится в табличной части самого объекта (у каждого объекта своя). **Дополнительное сведение** хранится в регистре сведений, значения для всех объектов в одной таблице. Читаются и пишутся они по-разному. **[надёжно]**
2. Свойство ищи по внутреннему имени (поле "Имя", предназначено для разработчиков), а не по наименованию: наименование пользователь меняет. **[надёжно]**
3. Не пиши значения в табличную часть реквизитов "в обход" механизма на форме: форма перезапишет их при записи. На форме используй вызовы подсистемы; прямое изменение допустимо только в программной записи без формы. **[проверить]**
4. Набор свойств привязан к виду объекта (и к группе, если у объекта есть группировка). Один набор может обслуживать несколько видов объектов; свойство, добавленное в другой набор, для объекта не видно. **[надёжно]**
5. Значение типа "Дополнительное значение" это ссылка на элемент списка значений свойства, а не строка. Сравнивай ссылки, не тексты.
6. Свойство должно быть включено в настройках программы (общие настройки, свойства), иначе механизм не подключён и на формах ничего нет. **[надёжно]**
7. Не придумывай сигнатуры. Названия и параметры процедур подсистемы возьми из её общего модуля в базе.

## Где что лежит (структура хранения)
| Элемент | Роль |
|---|---|
| План видов характеристик "Дополнительные реквизиты и сведения" | описание свойств (вид, тип значения, имя) |
| Справочник "Наборы дополнительных реквизитов и сведений" | какие свойства относятся к какому виду объекта или группе |
| Табличная часть объекта "Дополнительные реквизиты" | значения реквизитов этого объекта (поля `Свойство`, `Значение`) |
| Регистр сведений "Дополнительные сведения" | значения сведений (измерения `Объект`, `Свойство`, ресурс `Значение`) |
| Свойство "Характеристики" объекта метаданных | подключение свойств к отчётам и спискам как характеристик |

## Как читать
Запросом по таблице значений реквизитов объекта:

```bsl
Запрос = Новый Запрос;
Запрос.Текст =
    "ВЫБРАТЬ
    |	Реквизиты.Значение КАК Значение
    |ИЗ
    |	Справочник.Контрагенты.ДополнительныеРеквизиты КАК Реквизиты
    |ГДЕ
    |	Реквизиты.Ссылка = &Объект
    |	И Реквизиты.Свойство = &Свойство";
```
Свойство получи по имени из плана видов характеристик. Сведения читай запросом к регистру сведений по `Объект` и `Свойство`.
Для чтения значений нескольких объектов сразу предпочитай метод подсистемы для пакетной выборки (одним запросом), а не цикл по объектам. **[проверить]** имя метода в твоей версии.

## Как записывать
- Из формы объекта: вызовы подсистемы в `ПриСозданииНаСервере`, `ПередЗаписьюНаСервере`, `ОбработкаПроверкиЗаполненияНаСервере`; значения идут через механизм, не вручную. **[проверить]** сигнатуры по модулю в базе.
- Программная запись без формы: меняй строки табличной части объекта (добавь или обнови строку со свойством), затем запиши объект. Для сведений используй запись набора регистра или метод подсистемы. **[проверить]**
- После записи перечитай значение из базы и убедись, что оно сохранилось.

## В отчётах
Доп. реквизиты и сведения подключаются к отчёту как характеристики: в поле выбора ссылки доступны вложенные поля вида `Контрагент.<Свойство>`. Дополнительно подключать ничего не нужно, если у объекта в метаданных включены "Характеристики". Новый вариант отчёта с этими полями проще собрать пользовательской настройкой и перенести в вариант отчёта в конфигурации.

## Правила
- Не заводи на каждое мелкое поле дополнительный реквизит, если поле нужно в запросах высокой нагрузки: реквизит в табличной части плохо индексируется. Часто читаемое поле выноси в обычный реквизит расширения.
- Проверяй свойство на существование (по имени) до использования: набор может отсутствовать в другой базе или после обновления.
- Не удаляй и не переименовывай свойство с кодом, который его читает: имя является ключом.

## Как проверить
Тест-база: создать объект, задать значение через механизм, записать, прочитать запросом и через подсистему, сравнить. Для отчёта: скомпоновать с полем `Объект.<Свойство>` и убедиться, что значение пришло.

## Не проверено
Весь справочник сверен только по знаниям платформы: подсистемы «Свойства» и «ВариантыОтчетов» в конфигурации «Конвертация данных 3.1» (БСП 3.1.9.232) отсутствуют, проверить по ней нельзя, нужна ERP или УТ. Справочник `Свойства` в Конвертации данных относится к объектам конвертации обмена, не к подсистеме «Свойства». Точные имена объектов и параметры процедур подсистемы в твоей версии, поведение при нескольких наборах на один объект, обновление значений в фоне.
